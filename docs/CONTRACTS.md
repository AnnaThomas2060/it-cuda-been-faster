# Inter-Module Data Contracts

This document formalizes the typed contracts connecting Anna Thomas's pipeline, Pramod Goyal's verifier, and Mohamed Ziyadh Mohamed's analytics.

## Overview
All inter-vertical communication is structured through Pydantic models defined in `src.contracts`. This eliminates tight coupling and allows independent module development.

## 1. Kernel Evaluation Request (`KernelEvalRequest`)
Sent from Anna's pipeline (`src/pipeline/env_dispatcher.py`) to Pramod's verifier harness (`src/verifier/`).

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `task_id` | `str` | Unique operator task identifier from benchmark suite. |
| `code` | `str` | Candidate CUDA C++ source code generated by the policy. |
| `baseline_code` | `Optional[str]` | Reference baseline kernel code for relative comparison. |
| `turn_index` | `int` | Turn step within the current trajectory (0-indexed). |
| `timeout_seconds` | `float` | Hard timeout budget for compilation and execution. Default: 30.0s. |
| `device_id` | `int` | Target GPU device ordinal index. Default: 0. |

## 2. Kernel Evaluation Response (`KernelEvalResponse`)
Returned by Pramod's verifier harness (`src/verifier/`) to Anna's pipeline (`src/pipeline/env_dispatcher.py`).

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `task_id` | `str` | Unique operator task identifier. |
| `compiled` | `bool` | True if kernel compiled via nvcc without error. |
| `correct` | `bool` | True if numerical outputs match reference PyTorch tensors. |
| `execution_time_ms`| `Optional[float]` | Median kernel execution time in milliseconds. |
| `baseline_time_ms` | `Optional[float]` | Median baseline execution time in milliseconds. |
| `speedup` | `Optional[float]` | Speedup ratio (baseline_time_ms / execution_time_ms). |
| `memory_bandwidth_gbps` | `Optional[float]` | Measured memory throughput in gigabytes per second. |
| `baseline_bandwidth_gbps`| `Optional[float]` | Baseline memory throughput in gigabytes per second. |
| `compiler_output` | `str` | Diagnostic compiler messages, warnings, or nvcc logs. |
| `error_message` | `Optional[str]` | Stack trace or failure description if execution failed. |

## 3. Trajectory Step Sample (`TurnStepSample`)
Tracks intermediate states within a single trajectory rollout.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `turn_index` | `int` | Sequential turn index within the trajectory. |
| `prompt` | `str` | Formatted prompt presented to the model at this turn. |
| `thought` | `str` | Reasoning trace generated within `<think>` tags. |
| `code` | `str` | Extracted CUDA kernel source code. |
| `response` | `Optional[KernelEvalResponse]` | Execution and verification results from verifier. |
| `reward` | `float` | Intermediate reward assigned to this step. |

## 4. Telemetry Record (`TelemetryRecord`)
Appended to `logs/trajectory_telemetry.jsonl` by Anna's pipeline and consumed by Mohamed's analytics (`src/analytics/`).

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `trajectory_id` | `str` | Unique UUID for the rollout trajectory. |
| `task_id` | `str` | Benchmark task identifier. |
| `turn_index` | `int` | Turn index of the recorded evaluation. |
| `speedup` | `Optional[float]` | Achieved speedup over the reference baseline. |
| `reward` | `float` | Computed scalar reward for the turn. |
| `compiled` | `bool` | Compilation outcome flag. |
| `correct` | `bool` | Correctness verification flag. |
| `memory_bandwidth_gbps` | `Optional[float]` | Measured bandwidth utilization. |
| `timestamp` | `str` | ISO-8601 UTC timestamp. |
| `extra` | `Dict[str, Any]` | Optional dictionary for supplementary metrics. |
